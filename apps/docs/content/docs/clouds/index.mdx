A target is somewhere Loomplane can run a service or provision a resource. You connect an account for each cloud under **Integrations**, name targets in your manifest, and Loomplane builds and deploys with your credentials in your accounts.

<Callout type="warn">
  Managed cloud paths (Cloud SQL, RDS and the rest) are checked against controlled provider endpoints. Live cloud creation and recovery are not yet qualified, and the pages that depend on them say so. Run one against a disposable project in your own account before you rely on it.
</Callout>

## Connections

A connection holds the credential for one account. When you add one, Loomplane checks it with the cloud before it keeps it. A credential the cloud refuses is never stored. One that works but lacks permissions is marked incomplete, with every missing permission listed, until you fix it and check again.

Credentials live in Vault, encrypted with a key derived from your secret key. A connection stays usable for as long as a plan, build, binding or deployment references it, so don't delete one that's still in use. You can rotate a credential and keep the same destination.

| Cloud | You provide |
|---|---|
| [Google Cloud](/docs/clouds/google-cloud) | A service account key (JSON) |
| [AWS](/docs/clouds/aws) | An access key ID and secret, plus a region |
| [Vercel](/docs/clouds/vercel) | An access token, and a team ID if you deploy to a team |
| [Render](/docs/clouds/render) | An API key, and a workspace ID if it reaches several |
| [DigitalOcean](/docs/clouds/digitalocean) | A personal access token |
| [Azure](/docs/clouds/azure) | A service principal's client secret, with tenant, client and subscription IDs |
| [Your own servers](/docs/clouds/your-own-servers) | An SSH key and host key, or a Kubernetes kubeconfig |

## Clouds and targets

A Cloud (the organization-level object, with a capital C) groups named targets so your manifest can say `cloud_target: frontend` without carrying an account ID. You can also pick targets by tag. [Cloud targets](/docs/clouds/cloud-targets) covers that, and [Adopting and moving services](/docs/clouds/adopting-and-moving) covers changing accounts later.

## Pausing a target

During an incident on a cloud you can pause its target. Plans that use it are still made and can be approved, but they're for review only and deploy nothing. See [Monitoring](/docs/operations/monitoring#pausing-a-target).
