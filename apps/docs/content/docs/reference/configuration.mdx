---
title: Configuration
description: Every LOOMPLANE_ environment variable and config.yaml setting, with its default and the rules Loomplane enforces at startup.
---

Loomplane reads `config.yaml` from its config directory, then `config.local.yaml` beside it, with `LOOMPLANE_` environment variables wired into the YAML as `"${LOOMPLANE_SOMETHING:-}"`. A key in `config.local.yaml` wins over `config.yaml`. When a variable is unset, the built-in default applies. `loomplane` also loads a `.env` file from its working directory, if there is one.

The config directory is the current directory, or `LOOMPLANE_CONFIG_DIR`. The Docker image sets that to `/etc/loomplane`. `config.local.yaml` is ignored by Git, so it's the place for your own overrides. Keep secrets in the environment, not in either file.

## Core

| Variable | Default | Meaning |
|---|---|---|
| `LOOMPLANE_ENVIRONMENT` | `development` | `development`, `staging` or `production`. Production refuses the development secret key and an `http://` public URL |
| `LOOMPLANE_HTTP_ADDR` | `:8780` | Where the API listens |
| `LOOMPLANE_PUBLIC_URL` | `http://localhost:8780` | The address browsers and the CLI reach Loomplane at. Recovery and invitation links are built from it, and it's the issuer [keyless connections](/docs/clouds/keyless) trust, which needs https on a host the internet reaches. Must be an absolute URL, and https in production |
| `LOOMPLANE_SECRET_KEY` | A development key | 32 random bytes, base64 (`openssl rand -base64 32`). Every credential and secret is encrypted with keys derived from it. Keep it safe and away from your backups |
| `LOOMPLANE_DATABASE_URL` | Required | PostgreSQL DSN. Falls back to `DATABASE_URL`, which platforms like App Platform, Render, Heroku and Miget set for you |
| `LOOMPLANE_DASHBOARD_DIR` | `apps/dashboard/dist` | The built dashboard. Without one the API still runs and serves no dashboard |
| `LOOMPLANE_STORAGE_URL` | `.loomplane/storage` | Where deployment sources are kept, as `file:///path` |
| `LOOMPLANE_ARTIFACT_BUCKET` | `loomplane-artifacts` | The artifact bucket name |
| `LOOMPLANE_BACKUP_URL` | Unset | An independent backend for recovery objects, such as an S3-compatible URL. Empty uses the artifact backend |
| `LOOMPLANE_BACKUP_BUCKET` | `loomplane-backups` | The bucket for recovery objects |
| `LOOMPLANE_REQUIRE_EMAIL_VERIFICATION` | On when email is set up | Whether an account must verify its email before it can sign in or use the API. Unset, it's on wherever Loomplane can send mail (SMTP, Resend or a mail directory) and off where it can't, since nobody could get a code. `true` or `false` forces it; production refuses `true` with no mail. The account that runs first-time setup is verified by setup itself |
| `LOOMPLANE_SESSION_COOKIE` | `loomplane_session` | The HttpOnly session cookie's name. Cookies are shared by every port on a host, so another authsome app on the same host needs a different name |
| `LOOMPLANE_PASSKEY_RP_ID` | `public_url`'s host | The domain passkeys are bound to, such as `example.com`. A browser only offers a passkey on that domain or its subdomains. Changing it strands every passkey already registered, so set it before people add any |
| `LOOMPLANE_PASSKEY_ORIGINS` | `public_url`'s origin | Comma-separated origins people sign in from with a passkey, each on the RP ID or a subdomain of it. On `localhost` the page's own origin also works, so the Vite dev server needs nothing set |
| `LOOMPLANE_AUTHSOME_APP_ID` | Built in | The authsome app (`aapp_...`) that holds Loomplane's users |
| `LOOMPLANE_AUTHSOME_PUBLISHABLE_KEY` | Built in | That app's public key |

## Planning, drift and providers

| Variable | Default | Meaning |
|---|---|---|
| `LOOMPLANE_PLANNING_APPROVAL_WINDOW` | `168h` | How long a plan waits for a decision, from `1m` to `2160h` (90 days) |
| `LOOMPLANE_PLANNING_ENDPOINT_DENIED_CIDRS` | Unset | Ranges an endpoint check from a Kubernetes target never connects to, as a comma-separated list such as `10.20.0.0/16,192.0.2.7`. A bare address is one host |
| `LOOMPLANE_DRIFT_INTERVAL` | `30m` | How often deployments are compared with what's live. `0` turns it off. Otherwise at least `1s` |
| `LOOMPLANE_PAUSED_PROVIDERS` | Unset | Comma-separated target names whose plans are review only. A name that isn't a target stops startup |
| `LOOMPLANE_WORKER_HTTP_ADDR` | `:8781` | Where `loomplane-worker` serves its health checks |
| `LOOMPLANE_ANALYSIS_WORK_DIR` | System temp directory | Where checkouts are extracted during analysis |
| `LOOMPLANE_ANALYSIS_CONCURRENCY` | `2` | Analyses one worker runs at once. At least 1. Each can unpack up to 2 GiB |

Loomplane's own host, its database, its API and its provider plugins are always refused by endpoint checks, as are loopback, link-local and `0.0.0.0/8` addresses, AWS's IPv6 metadata service, and the NAT64 forms of all of these. Other private ranges are dialable, since real endpoints live there.

## GitHub

Set the five App settings together, or none. Loomplane refuses to start with some of them set. See [Private repositories](/docs/guides/private-repositories).

| Variable | Default | Meaning |
|---|---|---|
| `LOOMPLANE_GITHUB_API_URL` | `https://api.github.com` | GitHub's REST API, or your GitHub Enterprise Server's `/api/v3` |
| `LOOMPLANE_GITHUB_WEB_URL` | `https://github.com` | Where people install the App and sign in |
| `LOOMPLANE_GITHUB_APP_ID` | Unset | The App ID |
| `LOOMPLANE_GITHUB_APP_SLUG` | Unset | The App's slug |
| `LOOMPLANE_GITHUB_PRIVATE_KEY` | Unset | The PEM itself. Newlines written as `\n` work |
| `LOOMPLANE_GITHUB_PRIVATE_KEY_FILE` | Unset | The path to the PEM, instead of the key itself |
| `LOOMPLANE_GITHUB_CLIENT_ID` | Unset | The App's OAuth client ID |
| `LOOMPLANE_GITHUB_CLIENT_SECRET` | Unset | The App's OAuth client secret |
| `LOOMPLANE_GITHUB_WEBHOOK_SECRET` | Unset | The secret GitHub signs deliveries with. Empty turns webhooks off |

| `LOOMPLANE_BITBUCKET_CLIENT_ID` | Unset | The OAuth consumer's key |

## GitLab

Public projects on gitlab.com need none of this. Set the client ID and client secret together, or neither. Loomplane refuses to start with only one. See [GitLab repositories](/docs/guides/gitlab-repositories).

| Variable | Default | Meaning |
|---|---|---|
| `LOOMPLANE_GITLAB_API_URL` | `https://gitlab.com` | Where Loomplane reads gitlab.com from. Change it only to point at a test double |
| `LOOMPLANE_GITLAB_CLIENT_ID` | Unset | The Application ID of the OAuth application registered on gitlab.com |
| `LOOMPLANE_GITLAB_CLIENT_SECRET` | Unset | That application's Secret |
| `LOOMPLANE_GITLAB_ALLOW_ORGANIZATION_HOSTS` | `true` | Whether organizations may add a self-managed GitLab of their own. `true` or `false` |
| `LOOMPLANE_GITLAB_WEBHOOK_URL` | Unset | Where GitLab reaches the webhook, when the public URL isn't an address GitLab can reach. Empty uses `LOOMPLANE_PUBLIC_URL` |

Self-managed GitLabs that you trust are a list, so they have no variable. Put them under `gitlab.hosts` in `config.local.yaml`.

## Email

An empty host, with no Resend key or mail directory, disables email. Setting a username, password or sender without a host is an error.

| Variable | Default | Meaning |
|---|---|---|
| `LOOMPLANE_NOTIFICATIONS_MAIL_DIR` | Unset | Writes each email to this folder as an `.eml` file instead of sending it. Development only; production refuses it |
| `LOOMPLANE_NOTIFICATIONS_SMTP_HOST` | Unset | The SMTP server |
| `LOOMPLANE_NOTIFICATIONS_SMTP_PORT` | `1025` | Its port, 1 to 65535 |
| `LOOMPLANE_NOTIFICATIONS_SMTP_USERNAME` | Unset | Set with the password |
| `LOOMPLANE_NOTIFICATIONS_SMTP_PASSWORD` | Unset | Set with the username |
| `LOOMPLANE_NOTIFICATIONS_FROM` | Unset | A single sender address |
| `LOOMPLANE_NOTIFICATIONS_SMTP_TLS` | `false` | Implicit TLS, commonly on port 465. Production requires it |

## Push notifications

Loomplane can send phone notifications through a gateway that hands them to Apple and Google. A gateway address must use `https`, with no user info, query or fragment. In development, `http` works for `localhost`, `127.0.0.1` and `::1` only.

| Variable | Default | Meaning |
|---|---|---|
| `LOOMPLANE_PUSH_ENABLED` | `true` | Turn it off and the app hides push settings for this server |
| `LOOMPLANE_PUSH_GATEWAY_URL` | `https://push.loomplane.com` | The gateway that hands notifications to Apple and Google. Only XRaph's gateway can reach the store app |

## Nodes

Machines that join an organization hold one connection to a replica. When you run several replicas, a request for a node reaches the replica that holds it over a hop on `/_/nodes/hop`, signed with a secret every replica derives from `LOOMPLANE_SECRET_KEY`. With one replica you set nothing here.

| Variable | Default | Meaning |
|---|---|---|
| `LOOMPLANE_NODES_ADVERTISE_URL` (`nodes.advertise_url`) | Unset | Where the other replicas reach this one, such as `https://replica-a.internal:8780`. It must be an absolute http or https URL with no user, query or fragment, or startup stops. Set each replica's own address. Use `https`, or a private network with the setting below. With several replicas on one database and no advertise URL, each replica only reaches the nodes connected to it, and logs a warning when it meets one it can't |
| `LOOMPLANE_NODES_HOP_INSECURE` (`nodes.hop_insecure`) | `false` | Allow the hop over plain `http`. The hop carries stream bytes, so turn it on only on a private network |
| `LOOMPLANE_NODES_HOP_CA_FILE` (`nodes.hop_ca_file`) | Unset | A PEM file of the roots that verify the other replicas' certificates. Unset uses the system roots |
| `LOOMPLANE_NODES_JOIN_RATE_LIMIT` (`nodes.join_rate_limit`) | `10` | How many joins one address may send a minute. Past it the address gets a 429 until the minute is up. `0` turns the limit off |
| `LOOMPLANE_NODES_CHALLENGE_RATE_LIMIT` (`nodes.challenge_rate_limit`) | `120` | How many connect challenges one address may ask for a minute. Every node reconnects after a restart, and nodes behind one NAT share this budget, so raise it if you run more than about a hundred machines behind one address. `0` turns it off |

## Cloud sign-in

| Variable | Default | What it does |
|---|---|---|
| `LOOMPLANE_DIGITALOCEAN_OAUTH_CLIENT_ID` | Unset | The client ID of the DigitalOcean OAuth app (`clouds.oauth.digitalocean.client_id`). Set it with the secret |
| `LOOMPLANE_DIGITALOCEAN_OAUTH_CLIENT_SECRET` | Unset | The app's client secret. When both are set they apply to every organization and lock that cloud on the Cloud sign-in page |
| `LOOMPLANE_VERCEL_OAUTH_CLIENT_ID` | Unset | The client ID of the Vercel Integration (`clouds.oauth.vercel.client_id`). Set it with the secret and the slug |
| `LOOMPLANE_VERCEL_OAUTH_CLIENT_SECRET` | Unset | The Integration's client secret |
| `LOOMPLANE_VERCEL_OAUTH_SLUG` | Unset | The Integration's slug, the last part of its address on Vercel (`clouds.oauth.vercel.slug`). Required once the ID and secret are set |
| `LOOMPLANE_GCP_OAUTH_CLIENT_ID` | Unset | The client ID of the Google OAuth client (`clouds.oauth.gcp.client_id`). Set it with the secret |
| `LOOMPLANE_GCP_OAUTH_CLIENT_SECRET` | Unset | The OAuth client's secret |
| `LOOMPLANE_AZURE_OAUTH_CLIENT_ID` | Unset | The Application (client) ID of the Azure app registration (`clouds.oauth.azure.client_id`). Set it with the secret |
| `LOOMPLANE_AZURE_OAUTH_CLIENT_SECRET` | Unset | The app registration's client secret |

Each cloud's values lock only that cloud's row on the Cloud sign-in page, and they win over an app registered there. [Connect a cloud by signing in](/docs/clouds/cloud-sign-in) explains how to register each app, and every one of them uses `{public_url}/integrations/oauth/callback` as its callback.

## Cloud API endpoints

These exist so tests can stand fakes in for real clouds. Leave them empty in a live deployment.

`LOOMPLANE_GOOGLE_ENDPOINT`, `LOOMPLANE_VERCEL_ENDPOINT`, `LOOMPLANE_AWS_ENDPOINT`, `LOOMPLANE_RENDER_ENDPOINT`, `LOOMPLANE_DIGITALOCEAN_ENDPOINT` and `LOOMPLANE_AZURE_ENDPOINT` replace the matching cloud's API host.

The setting `clouds.enrollment_url` (set it in `config.local.yaml`) is the reachable HTTPS callback base that managed servers use to enroll. Empty uses the public URL, and a local address can't provision remote servers.

## Cloud capacity

<Callout type="warn">
  Automatic capacity is off by default and still being qualified. Turn it on only where you're ready for Loomplane to buy servers at your clouds on its own.
</Callout>

| Variable | Default | Meaning |
|---|---|---|
| `LOOMPLANE_AUTOMATIC_CAPACITY_ENABLED` | `false` | Lets pools add servers on their own, within each Cloud's capacity policy (`clouds.automatic_capacity.enabled`). Off, you can still save a policy on the Cloud's **Capacity** tab, but nothing grows and nothing waits for approval: a deployment that doesn't fit waits for a server you add. Pools never shrink on their own either way |

## YAML-only settings

These have no variable wired in `config.yaml`. Set them in `config.local.yaml`.

| Key | Default | Meaning |
|---|---|---|
| `database.pool_size` | `16` | Open connections. `0` keeps the driver's default |
| `orchestration.concurrency` | `4` | Jobs one process runs at once. At least 1 |
| `orchestration.poll_interval` | `1s` | How often idle workers look for jobs |
| `identity.base_path` | `/authsome` | Where authsome's API is mounted |
| `providers.plugins` | `[]` | A list of `{url, token}`. See [Provider plugins](/docs/extending/provider-plugins) |

`providers.paused` also accepts a YAML list, in place of the variable.

## AI

| Variable | Default | Meaning |
|---|---|---|
| `LOOMPLANE_AI_ENABLED` | `false` | Turns on the [AI section](/docs/ai) (`ai.enabled`): the Models and AI settings pages, their API and the model kinds. Off, a plan with a model resource gets a `catalog-feature-off` problem, and models already running keep running |
| `LOOMPLANE_AI_MODELS_HUGGINGFACE_URL` | `https://huggingface.co` | The Hugging Face Hub, or a mirror of it, that Loomplane reads repos, model cards and gated checks from, and that model engines download weights from (`ai.models.huggingface_url`). The workspace's Hugging Face token is sent there, so it must be https, with plain http allowed only for `localhost` or a loopback address. A user, query or fragment stops startup. vLLM and Text Embeddings Inference get a mirror as `HF_ENDPOINT`, and llama.cpp fetches its GGUF from it |
| `LOOMPLANE_AI_PROVIDER` | `anthropic` | The provider the infra agent uses by default (`ai.provider`): `anthropic`, `openai` or `openai-compatible`. Only read when `ai.enabled` is on |
| `LOOMPLANE_AI_API_KEY` | empty | The server's API key for that provider (`ai.api_key`). It's optional even with the agent on, because a workspace can bring its own key. Loomplane never logs it or serves it to the dashboard |
| `LOOMPLANE_AI_BASE_URL` | empty | The provider's endpoint (`ai.base_url`). You need it for `openai-compatible`, and it overrides the default endpoint for the others. It must be http(s) without a user or password, and https in production unless it's `localhost` |
| `LOOMPLANE_AI_MODEL` | `claude-sonnet-5-5` | The agent's default model (`ai.model`). It isn't the `ai.models` registry block below, which only says where model weights come from. The agent uses `claude-haiku-5-5` for cheap summarising steps |
| `LOOMPLANE_AI_EMBEDDING_PROVIDER` | empty | The provider for retrieval embeddings (`ai.knowledge.embedding_provider`): `openai` or `openai-compatible`. Anthropic has no embeddings API, so it can't be used. Empty turns retrieval off |
| `LOOMPLANE_AI_EMBEDDING_API_KEY` | empty | The key for the embedding provider (`ai.knowledge.embedding_api_key`). Never logged or served |
| `LOOMPLANE_AI_EMBEDDING_BASE_URL` | empty | The embedding endpoint (`ai.knowledge.embedding_base_url`). Required for `openai-compatible` |
| `LOOMPLANE_AI_EMBEDDING_MODEL` | empty | The embedding model (`ai.knowledge.embedding_model`). Required once a provider is set. Pick one whose native size is at most 2000 dimensions, such as `text-embedding-3-small` |
| `LOOMPLANE_AI_EMBEDDING_DIMENSIONS` | `1536` | The vector size (`ai.knowledge.dimensions`), from 1 to 2000. It must match the embedding model, and every workspace shares it, because the vector column has one fixed size. `text-embedding-3-small` at 1536 is the default |

With `ai.enabled` on, Loomplane checks these at startup and names the key that's wrong. With it off, none of them are checked, so a stray variable can't stop a server that doesn't run the agent.

`ai.prices` has no variable. Set it in `config.local.yaml` as a list of `{provider, model, input_per_million, output_per_million}`, in decimal USD such as `"3"` or `"0.80"`. The agent uses server prices only: nexus's own catalog, plus the models you list here. A price a workspace sets on its own provider key doesn't apply to the agent, so a model nexus doesn't know needs an entry here. Each provider and model pair can appear once.

## Process and container

| Variable | Meaning |
|---|---|
| `LOOMPLANE_CONFIG_DIR` | The directory that holds `config.yaml` |
| `LOOMPLANE_PROCESS` | `api` (default) or `worker`. The Docker image's entrypoint starts `loomplane` or `loomplane-worker` from it, for platforms such as Miget that drop `command:` overrides. Any other value stops the container |
| `LOOMPLANE_PORT` | The host port `make stack` publishes. Defaults to 8780 |
| `LOOMPLANE_URL`, `LOOMPLANE_API_KEY` | Used by `loomctl`, not the server |

The production Compose bundle also reads `LOOMPLANE_IMAGE`, `LOOMPLANE_DOMAIN`, `ACME_EMAIL`, `POSTGRES_PASSWORD`, `POSTGRES_IMAGE` and `CADDY_IMAGE`. See [Production on Docker](/docs/operations/production-on-docker).
