  Image:     {{ include "loomplane.image" . }}

The first API pod applies migrations before it starts, and the workers wait
for it. Follow along with:

  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "loomplane.fullname" . }}
  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "loomplane.workerName" . }}
  helm test {{ .Release.Name }} -n {{ .Release.Namespace }}

{{- if or .Values.ingress.enabled .Values.httpRoute.enabled }}

Setup needs a one-time token. Print the link and open it to create the first
account, which owns the instance:

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "loomplane.fullname" . }} -- loomplane setup-token

The first API pod also logs it as a "setup is waiting" warning.
{{- else }}

Nothing routes outside traffic to it yet: enable ingress or httpRoute, or try
it with a port-forward:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "loomplane.fullname" . }} 8780:{{ .Values.service.port }}
{{- end }}
{{- if and (le (int .Values.api.replicaCount) 1) (not .Values.api.autoscaling.enabled) }}

One API replica isn't highly available: a node drain or a crash takes
Loomplane offline until the pod is back. Set api.replicaCount to 2 or more.
{{- end }}
{{- if .Values.secrets.existingSecret }}

Using the Secret {{ .Values.secrets.existingSecret }}. With more than one
replica, its LOOMPLANE_STORAGE_URL has to point at S3 or the shared volume.
{{- end }}
